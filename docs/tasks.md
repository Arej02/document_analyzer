# tasks.md — Agent 1 (Understand)

Rule for this file: **every backend task that changes or adds an endpoint has a paired frontend task right under it**, so `frontend/` never drifts out of sync with what the backend can actually do. If you finish a backend task without touching its paired frontend task, you can build it but you can't test it end-to-end yet — don't check off the backend box until the frontend one is at least stubbed.

Frontend tasks assume your existing React app in `frontend/`; adjust file/component names to match what's actually there — these are written against the API contract in `design.md` §4, not against specific files I haven't seen.

- [x] `WordPressExtractor`: hooks, CPTs, meta — separate self-contained `Extractor` implementation from `PhpExtractor` (design.md §5), with its own subprocess script `backend/php/wp_extract.php` (same vendored `nikic/php-parser`, `composer install` needed under `backend/php/` — see the task above). It scans every file's whole AST (not just function bodies) for WordPress-signal calls — `add_action`/`add_filter` (registrations), `do_action`/`apply_filters` + `_ref_array` variants (invocations), `register_post_type` (CPTs), `register_post_meta`/`register_meta` — and evaluates their arguments to literal PHP values where possible (strings/numbers/bools/null/arrays), leaving anything computed at runtime as `null` rather than guessing. `backend/document_analyzer/worker/wordpress_extractor.py::WordPressExtractor` normalizes that into `ExtractionResult`, mapping onto the existing `entity_type`/`edge_type` enums (design.md §2 has no dedicated cpt/meta type): one `hook` entity per distinct hook name aggregating every registration/invocation occurrence in `raw_facts`; one `schema` entity per CPT/meta call site (`raw_facts["kind"]` = `post_type`/`meta`); a named or `Class::method`/`self::method` add_action/add_filter callback becomes its own lightweight `function` entity (`raw_facts.role = "hook_callback"`) with a `hook_binding` edge to the hook — closures, unresolvable callback shapes, and plain hook invocations (firing, not binding) get no edge; CPT/meta entities get no edges at all since no edge_type describes "defines a schema". ## Cross-cutting: keeping backend and frontend in sync going forward

Whenever you add or change an `/api/agent1/...` endpoint:

2. Add the backend checkbox here.
