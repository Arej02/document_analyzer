# tasks_report.md — Assessment Report (Codebase X-ray / Full Assessment)

Rule for this file (same as `tasks.md`, `tasks_agent2.md` and `tasks_agent3.md`): **every backend task that adds or changes an `/api/reports/...` or `/api/public/reports/...` endpoint has a paired frontend task directly under it.** Don't check off a backend box until its frontend pair can exercise the endpoint end to end. Backend tasks with no endpoint (migrations, pure modules, worker stages) need no frontend pair, and each says so.

The spec is `specs_report.md`. Contracts will live in `design_report.md` (written in Phase 0). If a task needs a contract change, update the design doc first, then this file, then the code (CLAUDE.md).

**Order (as requested):** estimator + `report_json` first, then rendering, then sharing. Work in small commits, one per checkbox unless it says otherwise. **There is a hard stop after Phase 4**: generate a report from a real repo in the database and show it before any visual polish.

### Frontend conventions
The same as `tasks_agent3.md`:
- No router. Pages are chosen by query param. The report adds `?report=<id>` with a `navigateToReport` helper.
- Every call goes through `useApiFetch()`. Errors render through `formatJobErrorMessage`.
- Reuse the `ProgressStages` stepper, the `risk-level-*` pills, `UnverifiedBadge`, `StatePanel` and `useCopy`.
- Every view ships with loading, empty and error states.
- Visual check: `vite build` plus a real browser pass.

### Prerequisites
- [x] **Agent 1: persist entity `risk_factors`** (`tasks.md`, "Assessment Report prerequisites"). Without it, §5.4 shows "signal not recorded" for every entity.
- [x] **Agent 1: persist `ingestion_jobs.discovery_stats`** (`tasks.md`, same section). Without it, §5.2 falls back to `workflow_events`.
- [x] **Agent 3: `unit_executions.started_at` / `finished_at`** (`tasks_agent3.md`, "Assessment Report prerequisite"). Without it, runtime estimates fall back to stage-level events and are flagged lower-confidence.

The report can be built before these land: each one has a fallback in `specs_report.md` §4, and tests cover both paths.

## Phase 2 — Estimator (pure module, no frontend pair)

- [x] `report/estimator.toml`: size-bucket edges, per-bucket cold-start defaults (cost, attempts, duration, failure rate), `min_samples`, Monte Carlo seed and runs, concurrency assumption, rework hours per failed unit by risk, manual-effort coefficients (per entity type, risk multipliers, per facade cycle, per oversized unit), optional `[pricing]` (currency, method, markup or unit rate, rounding, minimum), share-link expiry default and maximum, sparse-call-graph threshold. Loaded and validated by `report/config.py`, with a config hash.
- [x] `report/estimator.py`: pure functions, no DB. `bucket_units(units)`, `build_calibration(rows)` (aggregates only; drops `cost_usd = null` rows and counts them), `simulate(units, calibration, config)` (seeded, gives p50/p90 and n per bucket and overall for cost, runtime and rework), `manual_effort(facts, config)`, `quote(estimate, config)` (returns `None` without pricing; rounded). The output splits into a `customer` part and an `internal` part.
- [x] `report/calibration.py`: the only DB-reading piece of the estimate. Reads the pooled cross-org calibration set with the service role (decided 2026-10-01) from `llm_cost_by_execution_unit`, `unit_executions`, `clusters` and `cluster_reports`, plus unit timing (prerequisite) or stage events as fallback. It returns **aggregates only**: no org id, project id, path or unit id leaves this function. Stores a calibration snapshot id and date range.
- [x] `tests/test_report_estimator.py`: cold start (empty and below `min_samples`, which must say "defaults"), normal case against hand-computed fixtures, p50 ≤ p90 and n reported, mixed default and historical buckets, missing data (no plan risk, null sizes, unpriced rows above the threshold flag low confidence), seed determinism (same inputs give the same numbers), the failure rate adds rework, pricing absent gives no quote, and the `customer` part never has a cost field.
